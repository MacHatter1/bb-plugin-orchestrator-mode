# Orchestrator Mode 0.1.2

This release adds control over how workers run, makes reviewing their results explicit, and fixes watchdog warnings that interrupted legitimate delegation.

## Worker execution and workspaces

- Choose a worker's provider, model, reasoning level and permission mode per delegation, or set defaults with BB's provider/model picker.
- Save execution presets for build, review and research units. Per-call arguments override the preset and scoped defaults.
- Run units in the shared checkout, their own worktrees, or a mixed scope where each delegation chooses. Verification workers and configured retries reuse the unit's checkout.
- Configure one retry target for failed workers, parallel/per-turn delegation caps, and retention policies for completed workers.

## Scoped settings and review

- Configure project overrides for enforcement, worker execution, contract levels, caps, retention and appended rules. Projects without overrides inherit the global values.
- Record accepted or rejected worker results with `orchestrator_review`. The review gate reminds an idle orchestrator about results still awaiting a verdict.
- Request an independent check unit with `verify: true`; it inspects and reports rather than repairing the original worker's output.
- Inspect the exact contract with `bb orchestrator-mode contract`. Standard, review-heavy and delegate-only levels stay within the instruction budget.

## Delegation and watchdog fixes

- Provider/model pins take effect before a worker's first turn, with explicit execution provenance. Native `providerId` and CLI `--provider-id`/`--providerId` aliases remain supported.
- Follow-up messages to recorded workers count as delegation, including quoted stdin heredocs, even with shell exploration disabled.
- Literal `2>/dev/null` suppression is allowed on read-only commands. File-output redirects, executable substitutions and mutating `find` actions still count as work.
- Shell classification retains the stricter handling of writing flags, quoting, wrappers and mixed command chains. Program-running Git options are checked after directory and namespace operands too.
- Native and CLI delegation share scoped execution, caps, verification and retention. Resumed sessions can continue using CLI delegation when the native tool is unavailable.
- Timeline scans tolerate malformed rows and missing timing/sequence fields, judge reused row IDs correctly, and target the live turn when stopping work.
- Delegation caps and review reminders hold under concurrency; saved state and retained worker records remain bounded and sanitised.

## Upgrade notes

- Settings live in the plugin's Global/Project scope editor; unchanged projects retain inherited defaults. The new-thread default remains global.
- Provider pins are strict: if both `provider` and `providerId` are supplied, they must agree; a specified model must belong to the pinned provider. Blank pins are rejected after trimming.
- Worktree workers need any required environment setup committed in the repository. Worktree changes do not reach the shared checkout until a merge unit brings them in.
- `.github` and the GitHub Actions workflow have been removed. Verification uses the repository's local commands.
- The watchdog remains a coordination aid, not a security boundary; a fast write may complete before a stop request takes effect.
